Dual close-pair graph EXPERIMENT — NOT DEPLOYED

The visual layer today collapses every dual state (Top/Bottom, Attacker/Defender) into one hub node. This prototype splits them into adjacent node pairs — 2,637 nodes: 1,170 tight pairs + 297 singles — so the side you are playing is a real, visible place on the map. It ships inert: the code rides the bundle behind ?dual=fixed / ?dual=force, no flag means a byte-identical default, and nothing here changes the live product until the owner signs it off.

Viewing it live needs the prototype layout payloads, which are regenerable and deliberately not shipped: run python3 scripts/prototype_dual_pair_layout.py, then npm run dev and open http://localhost:8080/?dual=fixed or ?dual=force. Full plan (ordinal successors map, payload trade, camera notes): docs/DualPairMigration.md.

The two strategies, three zooms each

fixed = uniform 25° grain, perfectly regular 8.0u pair spacing. force = organic 6.1–11.7u, each pair finds its own axis. This is decision Q4 — the pictures are the evidence.

The ten open design questions

Surfaced by the prototype, decided by nobody yet — these gate the cutover.

  1. Q1 — Old share links: a retired hub ordinal arrives in a code. Light BOTH members, or only the primary (top/attacker)? Same for stored lists holding hub ids.
  2. Q2 — Defender edges: defender/bottom members carry only the pair tie (mirror edges would double every edge on screen). Keep them edge-light, or draw a subset?
  3. Q3 — Pair tie styling: ordinary link line today. Shorter/heavier/no line and rely on proximity?
  4. Q4 — Strategy: fixed vs force — the six images above.
  5. Q5 — Partner under focus: the focus halo currently swallows the twin at mid zooms. Co-lit dimmer, a side kicker label, or excluded from the halo?
  6. Q6 — Symmetric techniques: 297 singles have no role split. Single node right, or should symmetric techniques pair too?
  7. Q7 — Focus sets: should lighting a System/list co-light partners, or exactly the captured side?
  8. Q8 — Payload: compact pair encoding (engineering time) vs an accepted +47KB gzip boot cost.
  9. Q9 — First impression: should the weighted start draw a SIDE instead of always landing top?
  10. Q10 — Capture semantics: after cutover the coach's + captures a member. Is a class list of SIDES the product, or does capture normalize to the pair?
